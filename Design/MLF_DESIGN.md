**Что такое MLF?**

MLF - Malachite Language Frontend - предполагаемое API, которое позволит транслировать текст условного ЯП в последовательность IRCSH - Intermediate Representation Code Stack Handling - промежуточное представление кода стековой обработки. Данное API предоставляет (по задумке на данный момент): двухпроходной лексер с анализатором кодировок (он же CharacterAnalyzer), единую систему хранения информации TranslationContext, систему загрузки и обработки конфигов (на данный момент будет использовать ELDCL), функции и типы для работы с API. Предполагается, что TranslationContext, точнее его подсистема SemanticSystem, будет работать с Semantic units (символы, например, функции, типы и тд).



Ключевая идея - быстрое прототипирование языков программирования, хранения данных. В этом MLF помогают (будут) система конфигов и масок, стандартизированность IRCSH, AST, сборщике символов с учётом кодировок.



Необязательно использовать весь пайплайн, можно, например, вызывать только конфигуратор, лексер или сборщик AST/Парсер.



Описание языка создаётся с помощью конфигов.





**Как описывать языковые конструкции?**

Описывание языков конструкций производится с помощью конфигов, основанных на языке ELDCL.



Начнём с типов токенов. Они следующие:

* MLF\_NONE,
* MLF\_IDENTIFIER,
* MLF\_OPERATOR,
* MLF\_DELIMITER,
* MLF\_GKEYWORD,		//General Keywords: const, ptr
* MLF\_SKEYWORD,		//Syntax Keywords
* MLF\_LITERAL\_IDENTIFIER,	//true/false,null,nullptr
* MLF\_LITERAL



*Также предполагается добавление кастомных типов токенов, например, для атрибутов.*





Описание самих конструкций происходит с помощью MLFM - MLF Masks - языка масок. Он весьма простой по своей структуре. А его парсер будет использовать отдельный экземпляр лексера с собственной картой токенов, в частности, операторов.

Основные слова языка:

* STATEMENT - утверждение, не возвращает значение. Предполагается, что STATEMENT может быть как одиночным утверждением (инкремент переменной), так и блоком кода {}.
* EXPRESSION - выражение, возвращает значение.
* DIGIT - только цифра/последовательность цифр
* ANY - любая последовательность
* CHAR	- только 1 символ



Применение масок



$#key() - обозначение токена как опорного. Он занесётся в базу токенов как MLF\_SKEYWORD.



$#nsym() - указание обязательного  символа или последовательности символов (пакеты) определённой группы. Символы другой группы отклоняются, если маска не найдена, то выдаётся ошибка создания маски.

$#usym() - указание необязательного (u - unnecessary)  символа или последовательности символов (пакеты) определённой группы. Символы другой группы отклоняются, если маска не найдена, то выдаётся ошибка создания маски.





Пример:

tag::general\_construction VariableDeclaring

{

ASTType:VARIABLE\_DECLARING;

Mask: "$#exp($#MLF\_IDENTIFIER) $#key(:)  $#uexp($#MLF\_GKEYWORD...) $#exp($#MLF\_IDENTIFIER)";

}

Опорный пример - символ. Если его увидит парсер, то начнёт проверять все маски с этим символов для постройки AST узла.



Ещё примеры:

tag::literal Real32

{

&#x09;Map: "$#usym($#DIGIT...).$#nsym($#DIGIT...)f";

&#x09;DataType: "REAL32";	//Указание псевдонима в конфигурации! Его можно назвать External Compilation Time Identifier - ECTI - внешний идентификатор времени компиляции. То есть псевдоним для типов и других вещей внутри конфига для последующей связки с MFL в c++ коде.

}



tag::operator Ternary

{

OperatorType: OTernary;

Mask: "$#nsym($#EXPRESSION($#EXTERNAL\_SEMANTIC\_CHECKING\_TYPE)) $#key(?) $#nsym($#EXPRESSION($#ANY) | $#STATEMENT): $#nsym($#EXPRESSION($#ANY) | $#STATEMENT)"

Precedence: 5;

Associativity: RIGHT;

}

EXPRESSION($#ANY) = EXPRESSION

EXPRESSION предполагает под собой рекурсию, следовательно, должно быть обработано до этого. Хз, как это реализовать, как-нибудь выкрутимся

EXTERNAL\_SEMANTIC\_CHECKING\_TYPE - указание ЧИСЛОВОГО/ПРИМИТИВНОГО типа для семантической проверки. Тип должен быть описан в конфигурации. Поэтому сложные типы с методами не могут быть здесь представлены.

Как можно увидеть, все операции с ключевыми словами языка масок идут через $#.
